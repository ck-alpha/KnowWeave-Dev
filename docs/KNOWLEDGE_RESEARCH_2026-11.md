# KnowWeave 知识管理产品调研与补全建议

调研日期：2026-11-12（Asia/Shanghai）。面向本仓库已经明确的使用场景：个人科研、专题阅读、项目知识积累与本地模型问答。依据是官方产品文档、仓库源码和现有真实浏览器截图；未登录或实测第三方付费产品。文中的产品能力是文档事实，优先级与美学判断是针对 KnowWeave 的设计推论。

## 判断

KnowWeave 已经具备「资料 → Wiki → 专题阅读 → 带引用问答」的基础。最值得补全的环节是：从研究专题进入关系探索、分清知识之间的引用方向，以及把阅读中的证据与个人判断带到后续写作。继续增加独立入口，会放大现在各个模块之间的割裂感。

图谱的不足也不只是配色。现有首页像一本研究札记，图谱则更接近通用可视化工具。需要同时调整材质、排版和工作目的：让使用者知道自己正在探索哪个专题、为什么两个页面相连、接下来可以读哪一页。

## 六个相关产品与可借鉴之处

| 产品 | 已核对的官方能力 | 对 KnowWeave 的启发 | 不宜直接照搬的部分 |
| --- | --- | --- | --- |
| Obsidian | 全库图与局部图；局部图可调邻接深度；可显示引用方向、筛选孤立笔记；反链区区分已链接与未链接提及。[图谱](https://obsidian.md/help/Plugins/Graph%2Bview)、[反链](https://help.obsidian.md/plugins/backlinks) | 图谱应是阅读导航工具；方向与局部范围比增加视觉特效更有用。未连接页面值得成为整理入口。 | 不需要一次性搬入全部力导向参数。未链接提及属于候选线索，不能直接画成已有事实关系。 |
| Heptabase | PDF 摘录成为独立卡片，可放到白板并回到来源；写作流程可从选中的卡片链接开始，并在侧栏参照原卡片。[阅读与摘录](https://wiki.heptabase.com/pdf-annotation)、[写作流程](https://wiki.heptabase.com/a-simple-method-to-convert-your-thinking-into-writing) | 把「资料、自己的理解、文章产出」串联起来。专题和图谱之间应有直接入口；长期应建立有来源定位的证据摘录。 | 自动引用图和手工白板表达不同含义。不能让自由拖动或自动聚类暗示用户已确认的概念关系。 |
| Capacities | 可以查看一个对象、集合、标签、查询结果或对象类型的图谱；图谱与当前内容范围联动；反链提供可读列表。[图谱](https://docs.capacities.io/reference/graph-view)、[反链](https://docs.capacities.io/reference/backlinks) | 已有 Workspace 专题可以成为图谱范围。图与文字列表共同工作，用户不必仅靠节点位置理解关系。 | KnowWeave 当前的五种页面类型不是通用对象数据库，不必为对齐产品而扩张成大量对象类型。 |
| Tana Outliner | Supertag 给节点附加类型与字段模板；Search nodes 根据类型、字段、文本等条件形成动态查询。[Supertags](https://outliner.tana.inc/learn/features/supertags)、[Search nodes](https://outliner.tana.inc/learn/features/search-nodes) | 科研记录可以逐步提供一致模板，例如研究问题、证据、局限、下一步；常用筛选应能够重复进入。 | 先保持 Markdown 的可读性和迁移能力，不急于引入完整字段数据库或块级编辑器。 |
| Readwise Reader | Filtered Views 根据标签、作者、来源等条件组织资料，可以保存或固定入口，并按阅读位置分区；阅读过程支持高亮与注释。[筛选视图](https://docs.readwise.io/reader/docs/faqs/filtered-views)、[高亮与笔记](https://docs.readwise.io/reader/docs/faqs/highlights-tags-notes) | 把阅读队列变成可继续执行的工作清单；专题、状态、筛选和导航应保持一致。 | 当前已有收藏与阅读进度，不需要再造一套 Inbox/Later/Archive 状态并让两套概念竞争。 |
| Zotero | PDF 注释可以加入笔记，并带回原 PDF 页面的链接和引用；注释与正文引用可以继续用于写作。[PDF Reader and Note Editor](https://www.zotero.org/support/pdf_reader) | 科研可信度需要细到证据位置。页面级来源关系是起点，之后应支持摘录、页码/段落定位和书目信息。 | PDF/OCR 与引用格式不是一轮视觉改动可以顺带保证的能力，需要单独的数据设计和真实资料验收。 |

未纳入价格、订阅权益比较，避免把购买建议混入开发范围。Anytype 的旧文档入口本次未成功访问，因此未把未经核对的功能描述加入结论。

| 环节 | 已有实现与证据 | 实际缺口 |
| --- | --- | --- |

| 问答与复用 | [Query](../apps/web/src/app/query/query-view.tsx) 已能复制/导出回答与引用；模型返回 `suggestedNewPage` 时可保存新 Wiki，Chat 也有内容提升入口。 | [queryWiki](../packages/core/src/query.ts) 仍按全 Wiki 检索，没有专题范围契约；普通回答没有统一的持久研究记录与专题归档流程。 |

## 补全顺序与验收方式

优先级依据：是否直接减少日常研究中的上下文切换、是否复用已有数据、是否能清楚说明数据含义。下表是开发建议，不能当作已完成清单。

| 优先级 | 功能 | 最小完整范围 | 有意义的验收 |
| --- | --- | --- | --- |
| P0 · 本轮优先 | 专题图谱 | 从 Workspace 进入指定专题；Graph 能切换全库/专题；只显示范围内真实页面和两端都存在的引用。 | 空专题、已删除专题、组合搜索/类型筛选、2D/3D 切换、切 Wiki 后无旧专题残留；不捏造跨专题关系。 |
| P0 · 本轮优先 | 可读的引用方向 | 节点详情区分「此页引用」「引用此页」，双向引用明确展示；图上选择状态配合方向提示。 | 单向、双向、自引用和重复引用样例；统计区分有向边数与去重邻居数。 |
| P0 · 本轮优先 | 未连接页面入口 | 让没有真实页面引用关系的资料可发现、可选择、可进入编辑或阅读。 | 区分「全库无连接」和「当前筛选下看不到连接」；切换范围不会把普通页面误判为全库孤页。 |
| P0/P1 | 专题阅读清单导出 | 导出专题说明、页面链接、阅读状态和个人笔记，注明导出时间；保留 Markdown。 | 真实内容导出、中文/特殊字符、空专题、浏览器下载；明确它是清单而不是原始资料或完整 Wiki 备份。 |
| P1 | 专题范围问答 | API 明确传入专题或页面集合；BM25、Embedding、Hybrid 在同一候选范围内执行；回答展示实际范围。 | 空范围不调用模型、越界证据拒绝、索引状态仍准确；不能仅修改界面文案而继续检索全库。 |
| P1 | 有来源定位的摘录 | 先覆盖稳定文本来源，保存原文片段、来源 ID、位置与用户批注；原文改变时标记定位失效。 | 摘录往返定位、原文删除/修改、多次重复文本、引用导出、备份恢复；再扩展 PDF 页码。 |
| P1 | 研究问题与笔记模板 | 提供文献阅读/比较/决策模板；用户编辑后保存，不自动生成「已验证」结论。 | 模板只预填、不会覆盖现有内容；保存保持 Markdown 与既有来源规则。 |
| P2 | 未链接提及建议 | 根据标题/别名发现文字提及，展示上下文，用户确认后才写入 Wiki 链接。 | 中文分词、同名歧义、自提及、代码块/URL、撤销；建议关系与真实关系严格区分。 |
| P2 | 保存筛选与回顾 | 在已有专题/阅读状态基础上保存常用筛选，提供手动回顾入口。 | 筛选跨会话、跨 Wiki 隔离、已删除专题容错；不未经请求开启通知或定时任务。 |
| P2 | 文献互操作 | 优先支持可检查的 Zotero/BibTeX/CSL JSON 导入、去重与引用键映射，再考虑同步。 | 使用真实元数据样本与重复导入；不把单次导入宣称为双向同步。 |

第一阶段应聚焦关系探索与专题闭环；摘录、限定范围检索和 PDF 属于后续独立开发阶段。协作权限、移动端离线同步、完整块编辑器及 GraphRAG 需要更大的架构投入，目前没有证据说明它们比上述缺口更紧迫。

## 图谱的艺术方向：研究地图与页边札记

对照 [现有图谱截图](images/graph-2d-light.png) 与 [研究札记首页](images/workspace-home.png)，差异集中在三处：图谱的白色圆角工具外框比首页更像仪表盘；五彩珠光球的塑料质感与纸张/墨色不一致；多数节点的白色标签底板让文本看起来像悬浮控件，削弱了整体阅读秩序。这些是审阅判断，不是用户实验结论。

建议以现有首页为视觉标准：

1. **统一材质。** 使用同一暖纸/深纸底色与细分隔线；去掉强高光、发光球和过重阴影。节点采用哑光墨点、薄环或印记，保留足够清晰的选择状态。3D 继续可用，但材质也应像墨色陶质标记。
2. **统一色彩权重。** 绛红负责当前选择与主要动作；墨褐负责文字；铜、苔、灰蓝等低饱和色只帮助区分类型。类型同时保留文字，避免仅凭颜色表达含义。
3. **统一排版。** 大标题与节点详情使用同一衬线体系，控件沿用现有无衬线；页边索引承担说明与可读关系列表。普通文字/操作继续保持现有 18px，日期说明 16px，图谱密度标签可保留 14px。
4. **让视觉服务任务。** 首先说明当前范围，其次呈现图，最后呈现选中页的摘要与引用方向；删除重复说明和无依据的装饰关系。装饰线不能与真实引用混淆。
5. **以留白建立层次。** 减少胶囊与嵌套卡片，采用细线分区和适当的空白；标签按选择/悬停/重要连接分级，不能为保持简洁而隐藏所有可读名称。
6. **保持稳定可操作。** 默认不自动旋转；选中、切范围与返回全图可以预测；键盘焦点与减少动态效果保持有效。手机上将详情放到图下，不能依靠悬停才能完成任务。

本轮视觉验收应包含同一真实样例的桌面与窄屏、深浅主题、2D 与 3D，以及选中态、空结果、长标题和孤页。大规模图的性能与实际手机触控仍需独立验证，软件 WebGL 截图不能替代真实 GPU 测试。
