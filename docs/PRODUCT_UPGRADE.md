# KnowWeave 知识工作台升级

日期：2026-11-12（Asia/Shanghai）。审查基线：`06b911d`。本轮从科研与办公用户的持续使用流程出发，交付到当前私有开发仓库 `origin/main`，分阶段提交和推送。独立公开源码快照沿用独立发布流程。

## 用户与任务

科研用户需要围绕一个问题收集文献、比较证据、记录自己的判断，并在写作时找回依据。知识型办公用户需要按项目组织资料、标记阅读进度、积累可复用结论，并在上下文切换后继续工作。共同主线是：收集 → 整理 → 阅读与判断 → 提问取证 → 复用。

以下是根据当前源码推导的产品设计判断，不是用户访谈或已测量的留存结论。验收采用行为与数据一致性，不虚构转化率、满意度或效率提升百分比。

## 功能审查与优先级

| 环节 | 现有能力与证据 | 用户障碍 | 本轮决定 |
| --- | --- | --- | --- |
| 回到工作 | 首页总量与功能卡片（`app/page.tsx`） | 无法快速继续阅读或找到待处理资料 | P0：真实近期更新、阅读状态、待整理入口与下一步 |
| 按目标组织 | Wiki 类型、标签、多 Wiki 切换 | 同一 Wiki 内缺少课题/项目归类及个人阅读记录 | P0：专题、收藏、未读/在读/已读、个人笔记 |
| 查找资料 | Wiki 类型分组、命令面板、Sources 时间列表 | 页面变多后缺少组合筛选，待处理来源难定位 | P0：馆藏搜索/类型/标签/排序，资料搜索/状态/格式筛选 |
| 阅读判断 | Markdown、来源、反向链接、编辑和历史 | 长文定位与将内容带走的路径不足 | P1：文章目录、阅读时间估计、单页 Markdown 导出 |
| 提问复用 | 三模式检索、正文证据、引用、模型建议存页 | 新用户不知如何问，回答缺少连同问题的通用导出 | P1：研究/办公问题模板、复制/导出带引用回答 |
| 视觉与可用性 | 暖纸色/深红、中英界面、深浅色、图谱双视图 | 首页像功能目录；导航密集、层次和移动端体验不统一 | P0：统一外壳、任务导航、响应式知识工作台 |
| 可信度 | 原文追溯、检索状态、评测边界 | 容易把已读、模型置信度或离线指标误认为正确性保证 | 保留证据链；阅读状态只表示用户进度，笔记不进入模型证据 |

## 设计与数据边界

- 继续使用现有 Next.js、React、Markdown、SQLite 与本地模型；无需新增服务或依赖。
- 专题和个人阅读记录按 Wiki 保存到 SQLite，与正文、来源和检索向量分离。删除专题保留页面；删除页面清理其专题关系和阅读记录。备份需包含数据库。
- Wiki/来源目录搜索用于标题、标签等元数据查找；不把它宣传为新的语义检索或中文全文分词能力。
- 问答导出保留实际提交的问题、回答、引用、模型与检索方式；不自动保存到浏览器，不把编辑中的下一道问题套到上一次回答。
- 保持原有导入审批、索引刷新、Graph 双视图、Chat 与原文追溯。测试使用隔离样例，不写入个人 Wiki。
- 延续暖纸色、深红强调与中英混合界面，改善信息层次、键盘焦点、窄屏布局与深色模式；统计只来自真实数据。

实现期间可按实际依赖调整阶段边界；各阶段记录实际完成与未跑项，提交 SHA 在后续记录补齐。通过 Git 推送交付代码与文档；运行数据、缓存、个人资料与本地证据原件不提交。

## 后续候选（本轮不宣称已实现）

- 论文 PDF 的分页解析、图表/OCR、DOI/参考文献元数据：需要独立解析质量与授权样本验证。
- 专题级限定证据问答、引用格式、研究比较表：需要定义检索范围、缺失证据与导出协议。
- 中文检索专项、长文分块、任务取消/后台队列：需要独立质量与可靠性评测。
- 复习提醒、团队协作与云同步：需要用户调研以及权限/冲突/部署设计，不以本地个人工作台代替。
