## 本轮任务

### 任务一：核心用户路径稳定性与少量体验收尾（最高优先级）

- 在真实本地 Ollama（已有 `qwen3.8:27b` 和 Embedding 模型）环境，检查并必要时修复一条完整操作链：**导入来源 → Ingest 形成/更新 Wiki → 浏览 Wiki → 构建/刷新向量索引 → 选择 BM25/Embedding/Hybrid 提问 → 阅读有依据的回答 → 点击 Wiki 引用 → 追溯原始来源**。
- 保证用户看得懂检索模式和 Embedding 索引状态：未构建、文档更新后索引失效、模型未安装/离线、刷新成功/失败、无检索证据等场景应给出可理解的提示，不允许错误地宣称 Hybrid 成功或悄悄回退别的模式。
- 兼顾常见异常，如空输入、重复导入、来源或页面被删除、超长材料/上下文不足、模型响应异常等。只修影响实际使用和展示的关键问题；可修复明显的非阻断测试/警告，但**不要重构整个应用**。
- 本轮可以适当改善品牌、文字、布局和演示流畅度，但不要求全量 UI 重新设计；继续保持原有数据格式、既有 Wiki 兼容以及 BM25 在没有 Embedding 时仍可用。

### 任务二：形成一个可信、可复现的最终 Demo

- 以现有 **BEIR SciFact** 为唯一必选数据集，不再增加额外的大型数据集。准备可重复执行的演示流程或脚本：小样本导入、跨文档/增量更新、Wiki 查看、三模式检索、证据追溯。根据现有样本能力选择最能展示差异的 1–2 个有依据的问题，不要求所有模式必须在每个例子中表现不同。
- 用真实浏览器验证至少一遍完整路径，并获取适合公开展示的**真实项目截图**；如果条件允许，可提供简短 GIF/视频，但不是必须。截图不得伪造 UI 或 benchmark 结果，避免泄漏个人机器地址、用户名、密钥、私有 Wiki 内容。
- 检查干净环境的依赖、Ollama 配置、模型安装、索引构建和数据下载说明；给出最简启动及演示方式。若运行环境限制某些验证，如实记录，而不是写成已通过。

### 任务三：GitHub 门面与技术文档（核心交付）

- 重新整理 README，使招聘方快速看到：**KnowWeave 是什么、解决什么问题、展示图片、主要功能、系统架构、核心技术栈、如何启动、如何运行 Demo、Round 02 真实评测表、技术取舍与限制**。避免与源码不符的产品宣传。
- 突出可准确归属本项目的二次开发贡献：本地 Qwen/Ollama 适配、混合检索/向量索引维护、来源约束、可复现评测等；同时保留 `LICENSE`、`NOTICE.md` 和必要的版权/第三方归属，不把继承的完整产品能力写成全部从零原创。
- 检查现有 `architecture.md` 是否与最终源码一致，有必要才更新；避免维护多个互相矛盾的架构版本。开发日志和进度与代码同次提交保持一致。
- 如有必要清理无关的老品牌、误导性的营销内容、失效链接和模板文字，但不要破坏内部兼容变量/磁盘格式，也不要删除法定许可声明。

### 任务四：求职展示与面试材料

- 输出一份精炼、真实的求职项目说明（可以在 `docs/` 下以合适文件命名），包含：
  - **Agent 应用开发岗版本**：项目名、技术栈、个人实现的 3–4 条核心简历描述，强调检索系统、Ollama、Wiki 更新、工程评测；
  - **AI 产品经理实习版本**：用户问题、产品方案、关键用户流程、效果指标/权衡的 3–4 条描述；

- 数字必须取自已真实跑出的报告且写清范围，例如 SciFact 的 5,183/300、三路 Recall/nDCG/MRR。**Hybrid 的 Recall 低于 Embedding、nDCG 与 Embedding 差距极小，这一点不能隐藏或夸大为“全面领先”。**
- 重点帮助项目所有者解释“Wiki 与传统 RAG 的关系、为什么 BM25+Embedding、RRF 原理、更新失效策略、来源可追溯、离线指标与生成答案质量的区别、成本/延迟与工程权衡”，不需要写成长篇理论教材。

### 任务五：最终质量检查、交付日志与 Git

- 执行与改动相匹配的测试、类型检查、lint、生产构建，至少完成一次真实端到端演示，并记录能否正常启动、关闭和重新启动；如有相关指标变化，说明是由哪项真实改变引起，不默默替换 Round 02 历史结果。

## 最终验收标准

1. **产品闭环**：真实操作可以完成文档导入、Wiki 生成/更新、索引构建、三路模式切换、问答和来源追溯；关键失败场景不误导用户。
2. **技术可信**：已有 SciFact 原始数据检索 benchmark 可复现，真实指标和局限与源码一致；新增功能不是仅展示静态数字或伪造截图。
3. **工程可用**：按 README 能启动并演示，检查与构建结果真实，变更不破坏现有兼容性。
4. **面试友好**：README、真实截图、架构图/说明、简历描述和技术追问可直接用于实习投递。
5. **规范交付**：日志、进度、最终轮验收文档与提交推送齐备，隐私及开源许可合规。

## 本轮明确不做

不增加 MCP、GraphRAG、复杂多 Agent、第二套大型数据集、独立向量数据库、登录、多租户、云部署或大范围框架升级。中文检索、PDF/OCR、超长文档复杂分块、百万级性能优化等如非当前真实阻断问题，则写明局限，不强制开发。不要针对 SciFact test 标签调参争取更好成绩，也不要为了“完整产品”而无限加功能。
